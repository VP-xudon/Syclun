## 关于本实现：Syclun 解释器

本文档描述的是 **Synth-OOP 语言**（也写作 Synth OOP）的规范。当前对该语言的参考实现名为 **Syclun**。

**Syclun** 是 **Sy**nth-OOP **I**nterpreter **M**ade **o**f **C**PP **L**ang**u**age 的简称——「用 C++ 写成的 Synth-OOP 解释器」，读作 /ˈsɪklən/（近似「西克伦」）。字母取自该短语：**Sy** ← **Sy**nth-OOP，**c** ← **C**PP（即 C++），**l**、**u** ← **L**ang**u**age，**n** ← I**n**terpreter。

几点容易混淆之处：

1. **Syclun 是解释器的名字，不是语言的名字。** 语言叫 **Synth-OOP**；本文档是语言规范，与用哪种语言实现、由谁实现无关。换一个实现，语言依然是 Synth-OOP。
2. **CPP 指的是 C++ 编程语言**，不是 C 预处理器（C PreProcessor，通常缩写为 CPP，源文件扩展名也写作 `.cpp`）。Syclun 全部由 C++23 写成，除标准库外无任何依赖。
3. **这是合词简称，不是严格首字母缩写**，为便于发音而造，不要求逐字母严格还原。
4. **`synth`（可执行文件）≠ Synth-OOP（语言）。** Syclun 构建出的可执行文件名是 `synth`（`build/synth.exe`）；Synth-OOP 源文件的扩展名是 `.syn`（程序）、`.synl`（库接口）、`.syni`（接口声明）。
5. **附录 E 记录的是「当前实现」而非「规范」。** 附录 E 描述 Syclun 实际采纳的语义（含对前文某些章节的收窄与澄清）；它与前文冲突时以附录 E 为准，但那是实现的现状，不等于规范的未来方向。

## 一、开始之前：Synth OOP 想成为什么
一句话：**在编写时给予鸭子类型般的自由，在运行时提供静态类型般的安全。**
拆开说：
- **写代码的时候**，你不用到处贴类型标签、不用跟鸭子类型协商机制搏斗，数据想流到哪就流到哪，行云流水；
- **跑起来的时候**，每一次数据流动都经过严格的协议校验。出了问题不会崩溃、不会出现"未定义行为"，而是优雅降级。
这份"自由 + 安全"由五条设计定律支撑：万物皆对象、流式多态与智能协商、行为模式与约束系统、零值法则与物理铁壁、面向未来的 AI 协同。后文所有语法，都是这五条定律的具体落地。
### 鸭子类型与约束系统

Synth OOP 采用**鸭子类型**（Duck Typing）：一个对象是否是某种"类型"，不取决于它的声明，而取决于它是否具有所需的方法。

#### 为什么没有严格类型？

在 Synth OOP 中，**对象方法的实现是一个变量**——变量里面装的是行为。也就是说，方法可以被任意修改和替换。既然方法可以随时被替换，那么"类型"这个概念就没有意义了——**每个对象都是自己的类型**。

#### 系统原生对象的不可变性

虽然用户定义的对象的方法可以被任意修改，但**系统提供的原生对象（如 std::Number、std::String、std::Array 等）的方法都是常数行为（const behavior）**，即不可修改的。因此，你可以基于这个模型创建出与系统原生对象一模一样的、不可修改的对象。

#### 鸭式约束（Constraint）

虽然 Synth OOP 采用鸭子类型，但你仍然可以通过**约束**来显式声明一个对象必须具有的方法。约束是一张"方法清单"（在其他语言里常被称为接口 interface）：凡是拥有清单上全部方法签名的对象，都满足该约束。这与鸭子类型"按行为认对象"的思想一脉相承，只是把隐式的期待写成了显式的检查——一句话记住：**鸭子类型让你不用贴标签，约束让你想要标签时有标签**。

> 💡 **给新手的澄清：方法名里没有"点"，点只是调用符号**
> 你可能会看到文档里经常写 `a.+(b)`，于是以为方法名是"`.+`"（点加号）。其实不是：**方法名本身只有 `+` 这个符号**。那个"点"是**调用符号**——它表示"调用这个对象身上的方法"。`a.+(b)` 拆开看是：`a`（对象）`.`（调用）`+`（方法名）`(b)`（传参）。所以声明方法时写 `@+ << ...`（方法名就是 `+`），调用时才写 `a.+(b)`。这一点和你在其他语言里写 `a.add(b)` 的 `.` 是一样的——点号永远只是"调用"这个动作，不是方法名的一部分。

约束的完整语法——如何定义约束、直接用类名当约束、约束继承，以及参数限定方括号 `[]` 里的行为限定符 `@`——将在第九章专门讲解。

小贴士：如果你之前接触过 C++、Java 或 Python，你会发现 Synth OOP 吸收了很多语言的精华，同时又做了一些大胆的创新。别担心，本文档会从零开始讲起，你不需要任何前置知识。

## 二、万物皆对象

### 2.1 没有"基本类型"
很多语言里，int、bool 是特殊的"基本类型"，要包装一下才变成对象。Synth OOP 不做这种二元划分——**从数字到业务逻辑，一切天生就是对象**：

| 概念 | Synth OOP 类型 |
| ---- | -------------- |
| 数字 | `std::Number` |
| 布尔 | `std::Boolean` |
| 字符串 | `std::String` |
| 数组 | `std::Array` |
| 字典 | `std::Dict` |
| 元组 | `std::Tuple` |
| 万物之源 | `std::Object` |

`std::` 是命名空间，相当于这些类型的"姓氏"，表示它们都属于 Synth 家族。
一切皆对象的直接好处：**所有数据天生具备行为能力**。任何数据都可以调用方法、链式组合、被注入行为——数据和方法之间没有鸿沟。

### 2.2 原生对象：交给编译器实现的底座
在 Synth OOP 中，所有对象都是原生对象——它们不是靠库拼出来的，而是编译器必须直接内建实现的底座。这意味着语言中没有"标准库对象"和"原生类型"的区分，每一个对象都由编译器亲自实现。
完整的原生对象列表如下：

| 原生对象 | 说明 |
| -------- | ---- |
| `std::Number` | 数字（数值类型），语言内建的数值对象 |
| `std::Boolean` | 布尔值，true / false |
| `std::String` | 字符串，不可变字符序列 |
| `std::Array` | 数组，对标 C++ 的 std::vector，动态可增删 |
| `std::Dict` | 字典，键值结构的数据容器，支持动态增删键值对 |
| `std::Object` | 万物之源，所有对象的基类 |
| `io::OStream` | 输出流，对标 C++ 的 ostream，提供标准的输出能力 |
| `io::IStream` | 输入流，对标 C++ 的 istream，提供标准的输入能力 |
| `std::Tuple` | 元组，按位置排列的不可变值序列，用于多返回值与结构化绑定 |

注意：`io::OStream` 和 `io::IStream` 不能直接当作对象使用，必须先实例化（声明变量）后才能调用其方法或参与流操作。

> ⚠️ 本节写给编译器开发者：以上原生对象都属于编译器要实现的范畴，而不是普通类库。它们的**内置方法规格见下一节（2.3）**。

### 2.3 原生对象的内置方法

所有原生对象的方法都由**编译器直接内建实现**（不是库函数）。下面按对象列出其内置方法（方法名 + 参数 + 功能），供编译器开发者实现时参考。方法定义的语法见第 6.1 节；参数的类型限定方括号 `[]` 里可以填行为限定符 `@`（见第九章）。

#### 2.3.1 万物之源 `std::Object` 与通用机制

任何类若不显式写父类，默认继承 `std::Object`。因此构造函数 `::`、析构函数 `~`、公布函数 `=:`、接收函数 `:=`、赋值方法 `=`，统一在 `std::Object` 处定义，并以 `@!`（方法变量 const）设为**不可修改**：

```text
$Object {
    @!:: << [() ~> () {}];                      // 构造：对象创建时调用
    @!~ << [() ~> () {}];                       // 析构：对象销毁时调用
    @!=: << [() ~> (result) { /* 公布自身值 */ }];  // 公布：流语句的发送方；默认配合接收方，原样公布自身
    @!:= << [(value) -> () { /* 接收 value */ }]; // 接收：流语句的接收方；当 value 与自身类型一致时，默认直接拿 value 赋值自身（流式赋值的底层来源）
    @= << [(value) -> () { /* 用 value 赋值自身 */ }]; // 赋值：a.=(b)，与 a << b 的赋值用法等价
}
```

> **注（v1.27）**：历史上 `std::Object` 还定义过异常捕获方法 `_case` 与隐式属性 `error`（"毒水标记"），用于沿数据流传播错误。这些已在当前实现中**退役**：错误现在于源头即时抛出并以类 g++ 的诊断（含执行栈）报告，运行期合法性检查改用标准库 `&assert;` 的 `Checker`（`has_method` / `has_changed`）。

#### 2.3.2 各原生对象的内置方法（逐方法功能说明）

下面用 Synth OOP 自身的方法定义语法，逐个说明每个原生对象的内置方法。每个方法的花括号内以注释描述它要实现的**具体功能**。

**`std::Number`（数字，数值类型）**

```text
$Number {
    @+ << [(std::Number other) => (std::Number result) {
        // 加法：result = self.+(other)
    }];
    @- << [(std::Number other) => (std::Number result) {
        // 减法：result = self.-(other)
    }];
    @* << [(std::Number other) => (std::Number result) {
        // 乘法：result = self.*(other)
    }];
    @/ << [(std::Number other) => (std::Number result) {
        // 除法：result = self./(other)；other 为 0 时 result 带毒（error 置为错误信息）
    }];
    @% << [(std::Number other) => (std::Number result) {
        // 取模：result = self.%(other)
    }];
    @< << [(std::Number other) => (std::Boolean result) {
        // 小于比较：result = (self.<(other))
    }];
    @> << [(std::Number other) => (std::Boolean result) {
        // 大于比较：result = (self.>(other))
    }];
    @<= << [(std::Number other) => (std::Boolean result) {
        // 小于等于：result = (self.<=(other))
    }];
    @>= << [(std::Number other) => (std::Boolean result) {
        // 大于等于：result = (self.>=(other))
    }];
    @== << [(std::Number other) => (std::Boolean result) {
        // 相等比较：result = (self.==(other))
    }];
    @!= << [(std::Number other) => (std::Boolean result) {
        // 不等比较：result = (self.!=(other))
    }];
    @to_string << [() => (std::String result) {
        // 把 self 转为十进制字符串表示
    }];
    @repeat_ << [(body) -> (value) {
        // 循环：self 为循环次数（Number），body 为循环体行为；
        // body 形如 [(state) -> (state)]，其参数格式必须等于返回格式；
        // value 为最后一次执行 body 的返回值
    }];
}
```

**`std::Boolean`（布尔值）**

```text
$Boolean {
    @if_ << [(true_branch, false_branch) -> (value) {
        // 条件分支：self 为真时执行 true_branch，否则执行 false_branch；
        // value 为所执行分支的输出，两个分支的输出类型必须一致
    }];
    @while_ << [(body, condition_check) -> (value) {
        // 循环：self 为初始条件（Boolean），body 为循环体行为，condition_check 为条件检查行为（在 body 之后）；
        // body 形如 [(state) -> (state)]，其参数格式必须等于返回格式；
        // condition_check 形如 [(state) ~> (flag)]，其参数格式必须等于 body 的返回格式；
        // value 为最后一次执行 body 的返回值
    }];
}
```

参数说明：`true_branch`、`false_branch`、`body`、`condition_check` 均为**行为（behavior）**。`repeat_` 不属于本对象——它是 `std::Number` 的方法。

**`std::String`（字符串，不可变字符序列）**

```text
$String {
    @+ << [(std::String other) => (std::String result) {
        // 字符串拼接：result = self.+(other)，返回新字符串（原串不变）
    }];
    @upper << [() => (std::String result) {
        // 转大写，返回新字符串
    }];
    @lower << [() => (std::String result) {
        // 转小写，返回新字符串
    }];
    @reverse << [() => (std::String result) {
        // 反转字符顺序，返回新字符串
    }];
    @length << [() => (std::Number result) {
        // 返回字符个数
    }];
    @get << [(std::Number index) => (std::String result) {
        // 返回第 index 个字符（index 从 0 开始）
    }];
    @contains << [(std::String sub) => (std::Boolean result) {
        // 判断 self 是否包含子串 sub
    }];
    @slice << [(std::Number start, std::Number end) => (std::String result) {
        // 返回 [start, end) 区间子串
    }];
}
```

**`std::Array`（数组，对标 C++ 的 std::vector，动态可增删）**

```text
$Array {
    @push_back << [(value) -> () {
        // 在末尾追加元素 value（对标 vector::push_back）
    }];
    @get << [(std::Number index) ~> (value) {
        // 按索引取元素，index 从 0 开始；也可命名为 query
    }];
    @size << [() ~> (std::Number result) {
        // 返回元素个数
    }];
    @pop_back << [() -> () {
        // 移除末尾元素
    }];
    @remove << [(std::Number index) -> () {
        // 删除第 index 个元素
    }];
    @insert << [(std::Number index, value) -> () {
        // 在第 index 个位置插入 value，后续元素后移
    }];
    @clear << [() -> () {
        // 清空所有元素
    }];
    @front << [() ~> (value) {
        // 返回首元素
    }];
    @back << [() ~> (value) {
        // 返回末元素
    }];
}
```

> `push_back` 为 Array 的**正式内置方法**（Array 对标 `std::vector`，动态可增删），并非被废除的方法。

**`std::Dict`（字典，键值结构，支持动态增删键值对）**

```text
$Dict {
    @get << [(key) ~> (value) {
        // 按键 key 取值；键不存在时返回该值类型的零值（历史上的"毒水"兜底已退役）
    }];
    @set << [(key, value) -> () {
        // 设置键值对；键已存在则覆盖
    }];
    @remove << [(key) -> () {
        // 删除键 key 对应的键值对
    }];
    @has << [(key) ~> (std::Boolean result) {
        // 判断是否含键 key
    }];
    @size << [() ~> (std::Number result) {
        // 返回键值对数量
    }];
    @keys << [() ~> (std::Array result) {
        // 返回所有键组成的数组
    }];
    @values << [() ~> (std::Array result) {
        // 返回所有值组成的数组
    }];
}
```

**`std::Tuple`（元组，按位置排列的不可变值序列）**

```text
$Tuple {
    @get << [(std::Number index) ~> (value) {
        // 按索引取元素，index 从 0 开始
    }];
    @make << [(elements) => (std::Tuple result) {
        // 从若干元素构造元组，elements 为按位置排列的任意对象
    }];
    @size << [() ~> (std::Number result) {
        // 返回元素个数
    }];
}
```

> 元组的**字面量初始化** `-(std::Tuple t) << (10, "Alice", true)` 与**结构化解耦** `-(std::Number q, std::Number r) << t` 由编译器直接实现，不属于方法调用。

**`io::OStream`（输出流）**

```text
$OStream {
    @!:= << [(value) ~> () {
        // 接收函数（常数模式 ~>）：把 value 输出到标准输出；
        // 不修改 out 自身状态，因此 out 可声明为常数
    }];
}
```

**`io::IStream`（输入流）**

```text
$IStream {
    @!=: << [() ~> (result) {
        // 公布函数（const 语义）：从标准输入读取数据并公布到 result；
        // 不修改 in 自身状态，因此 in 可声明为常数
    }];
}
```

> 说明：`std::Number` 即"数字"，`std::Float` 已被替代（见 5.5 节澄清）。上述所有对象默认继承 `std::Object`，故 `::`、`~`、`=`、`=:`、`:=` 均自动拥有，无需重复实现。（历史上的 `_case` 与 `error` 属性已退役，见 v1.27 实现状态提示。）

### 2.4 程序本身也是对象
程序的入口 `$Program` 本身就是一个对象实例：
- 编译器启动 = 实例化 `$Program`
- 程序执行 = `$Program` 的生命周期
这样做消灭了"全局作用域"的混沌——程序的启动有明确的边界和上下文，一切都有主。

## 三、流语句（Streaming）
流语句是 Synth OOP 的核心动作：**让数据从一个对象流向另一个对象**。

### 3.1 两种写法，一个意思

```text
<对象 A> >> <对象 B>; // A 流向 B
<对象 B> << <对象 A>; // 与上式完全等价
```

两种写法语义完全相同，选读起来顺手的即可。

### 3.2 例子

```text
&io;
-(std::String txt);
-(io::OStream out);
-(io::IStream in);
out << "Yeah.";
out << txt;
in >> txt;
```

小贴士：注意这里我们同时声明了 out（输出流）和 in（输入流），并通过 `&io;` 导入了 io 命名空间。因为 OStream 和 IStream 是原生对象，不能直接用，必须先实例化。

### 3.3 流动的背后：智能协商
数据不是蛮力灌进去的。每次流动之前，发送方与接收方会进行一次"外交握手"，通过内置协议自动协商兼容性：
- **协商成功**：数据顺利流入；
- **协商失败**：绝不发生隐式暴力转换（不会出现 `"1"+1="11"` 这种闹剧），系统平滑降级，返回一个安全的空对象，程序不崩溃。
这就是"编写时自由、运行时安全"的关键技术手段：你尽管流，协议替你兜底。

### 3.4 Out 流的特殊语义：向流写入不是修改环境变量
在 Synth OOP 中，向 `io::OStream` 写入数据（例如 `out << "Hello"`）**不是修改环境变量**，而是一种特殊的"通信"操作。理解这一点，需要搞清楚 `Out` 的接收函数（`:=`）为什么是特殊的。

#### 3.4.1 接收函数是 const 的
`io::OStream` 的接收函数 `:=` 被定义为**常数模式**（`~>`）。无论它接收什么对象，它的接收函数本身都不会修改接收方自身的状态——它只是"收下"数据并执行输出动作。换句话说，`out << "Hello"` 不会改变 `out` 对象本身，它只是让 `out` 把 `"Hello"` 打印到标准输出。
这与一般的内置对象完全不同。对一个普通的 `std::Number` 做 `x << 5` 是修改了 `x` 的值，但向 `io::OStream` 做 `out << "Hello"` 并没有修改 `out` 的状态。

#### 3.4.2 流语句的本质
流语句的底层执行顺序是：
1. **先调用发送方的公布函数 `=:`** —— 发送方把自己要传出的值"发布"出来；
2. **再调用接收方的接收函数 `:=`** —— 接收方"接收"这个值，执行相应的操作（对于 `OStream` 就是打印输出）。
这两个步骤通过智能协商协议自动完成。发送方和接收方各自履行自己的职责，互不干扰。

这同时回答了另一个问题：**赋值为什么能直接借用流语句的语法**。所有原生对象的接收函数 `:=` 都带有一个默认实现——**当流入的值与接收方类型一致时，直接拿对方来赋值自己**；与此同时，发送方的公布函数 `=:` 也会配合，把自身原样公布出去。于是同类型之间的 `a << b` 天然就是"把 b 赋给 a"。你也可以绕过流语句，显式调用赋值方法写作 `a.=(b)`，效果完全等价——只是流式写法更直观，也更贴合语言"数据流动"的哲学（见 4.3 节）。

#### 3.4.3 Out 可以声明为常数
正因为 `Out` 的接收函数不修改自身，你可以在声明 `Out` 时把它声明为常数：

```text
-(io::OStream! out);
out << "Hello"; // 合法！out 虽然是常数，但写入操作不修改 out 自身
```

这在一般的内置对象中是不可能的——如果你把一个 `std::Number` 声明为常数，任何试图修改它的操作都会被编译器拦截。但 `io::OStream` 是特殊的：它的"写入"本质上是副作用操作（输出），而不是状态修改。

> 小贴士：`io::IStream` 的公布函数 `=:` 同样具有类似的 const 语义——读取输入不修改 `IStream` 自身的状态。因此 `IStream` 也可以被声明为常数。

## 四、对象实例化语句（表达式）
在 Synth OOP 中，创建对象（即类的实例）的语句正式称为**对象实例化语句**。你可能在其他语言里见过"变量声明""变量定义"这样的说法，但在 Synth OOP 里，每一个变量都是一个对象，所以"对象实例化"才是更准确、更本质的叫法。
更重要的是——**对象实例化语句本身也是一个表达式**。它的值就是新创建出来的那个空对象。这意味着声明不再是孤立的"动作"，而是数据流的一部分，可以参与运算、方法调用，甚至直接流入下一个对象。

### 4.1 标准对象实例化
语法格式为：`-(类型名 变量名);`
这与大多数面向对象语言的声明方式一致，但有一个关键区别：行首的 `-` 后面紧跟一个圆括号 `()`，括号内是类型名和变量名。这个圆括号标志着"这是一个实例化表达式"。

> 💡 **给新手的澄清：实例化时"必须"带原型名**
> 圆括号里必须写 **`类型名 变量名`** 两项，**不能只写变量名**（不能写成 `-(num)`）。因为实例化语句做的不是"给已有的东西起个名字"，而是"按某种原型新建一个对象"。类型名（也叫**原型名**，例如 `std::Number`、`Student`）决定了要实例化哪一个类、新对象具备哪些方法和行为。如果只写变量名而不写原型名，编译器无法知道你要实例化什么，只能退而生成一个**系统默认的空对象**——它没有任何方法和可用的状态，你拿到它也无法正常操作。所以请记住：**凡是 `-(...)` 的对象实例化，圆括号里都必须是 `-(原型名 变量名)`，原型名不能省略。**

```text
-(std::Number a); // 声明并实例化一个 std::Number 对象 a
-(Student b); // 声明并实例化一个 Student 对象 b
```

小贴士：`-` 前缀是 Synth OOP 的一个标志性设计。它让你一眼就能看出"这是一条对象实例化语句"。圆括号 `()` 则明确告诉你"这里在创建一个新对象"。

### 4.2 声明并赋值
语法格式为：`-(类型名 变量名) << 值;`

```text
-(std::String strlock) << "Yahoo!";
```

### 4.3 赋值为什么用 `<<`
在 Synth OOP 里，赋值不是"相等"，而是"流动"：**把数据流入变量**。这和第三章的流语句是同一套机制，方向读起来很直观——右边的东西流进左边。
你可以把 `<<` 想象成一条管道：数据从右边出发，沿着管道流进左边的变量里。
注意：**`=` 不是 Synth OOP 的运算符**，中缀写法 `a = b` 是非法的。赋值之所以能借用 `<<`，是因为所有原生对象的接收函数 `:=` 默认在"对方与自己类型一致"时直接拿对方赋值自己，而发送方的公布函数 `=:` 也会原样配合（详见 3.4.2 节）。你也可以显式调用赋值方法，写作 `a.=(b)`，与 `a << b` 的赋值用法完全等价——但流式写法更符合语言的流动哲学，推荐始终使用 `<<`。

### 4.4 零值法则
变量在声明（分配内存）的瞬间，就自动初始化为该对象的**零值**。也就是说，Synth OOP 的世界里不存在垃圾值、不存在悬空指针、不存在"未定义"。这里没有"虚无"的深渊，只有"零"的宁静。
为什么这很重要？想象一下你在写一个大型项目，如果某个变量拿着一个随机的垃圾值，调试起来会是多么令人抓狂。零值法则从根本上消灭了这类问题：你声明了变量，它就有一个确定的、安全的初始值。

### 4.5 常数标记：类型名后加 `!`
在类型名后面加一个 `!`，表示该变量为常数。任何试图修改它的行为，都会被编译器像铁壁一样无情拦截（详见第十一章）。

```text
-(std::Number! frozen) << 7;
```

frozen 被声明为常数，后续任何尝试对 frozen 赋值的操作都会触发编译期报错。
注意：`!` 紧跟在类型名之后、变量名之前，这是常数变量的唯一语法形式。不再有独立的 `!!` 后缀标记。

### 4.6 实例化表达式：声明即数据
这是本章最重要的设计——**对象实例化语句是一个表达式，它的值就是新创建出来的那个空对象**。这意味着你可以把声明直接嵌入到任何表达式中，让它参与运算、方法调用、流操作：
**直接参与流语句：**

```text
&io;
-(io::OStream out);
-(std::String msg) << "Hello";
out << (-(std::String msg2) << "World"); // 声明 msg2 并赋值，表达式值就是 msg2 对象本身
out << msg;
```

在这个例子中，`(-(std::String msg2) << "World")` 是一个表达式，它的值就是 msg2 对象（包含字符串 "World"）。这个值可以直接被 `out <<` 消费。
**直接调用方法：**

```text
-(std::String result) << ("hello").upper(); // 如果 upper() 是 String 的方法
```

**链式组合：**

```text
-(std::Number sum) << ((-(std::Number a) << 10).+( -(std::Number b) << 20));
```

这里先声明并初始化 a（值为 10）和 b（值为 20），表达式值分别是这两个对象，然后执行加法运算，最后将结果流入 sum。

> **注（v1.27）**：历史上的"毒水模型"曾用"对象在诞生瞬间就携带毒性、沿数据流传播"来描述错误的表达。当前实现已退役该模型——错误在发生的**源头即时抛出**，并以类 g++ 的诊断（含出错源码行、插入符与完整执行栈）报告。例如 `a./(0)`（除以零）按 IEEE 754 直接得到 `Infinity`/`NaN`（不会中断），而真正的语义错误（类型不符、方法缺失等）会立即中止并报错，不再"融入数据流"。

## 五、行为及其模式

### 5.1 什么是行为
"行为"（behavior）是 Synth OOP 里可执行逻辑的基本单元，用**方括号包裹**书写：

```text
[(输入参数…) 行为模式 (输出…) { 函数体 }]
```

- 第一个括号：输入参数（参数列表，本质是元组声明，顺序与方法签名严格匹配）
- 中间：行为模式（`=>`、`~>` 或 `->`，见 5.2 节）
- 箭头之后：输出结果（方法签名 + 输出参数名）
- 花括号内：函数体（具体做什么）

> 💡 **`void` 关键字已退役——用空括号 `()` 表示「无值」**
> Synth OOP 的语言哲学**允许行为不公布任何值**：只需写**空输出列表**即可，例如 `[() -> () {…}]` 或 `[(x) -> () {…}]`。输出列表为空的行为不公布任何值（故 `out << 不返回值的行为` 不打印任何内容），其列出的每个输出都照常公布。在类型、变量名、输出名、约束名位置书写 `void` 现在都是**语法错误**（`'void' is not a type or name; use empty parentheses '()' …`），由语法分析器强制。

> 💡 **给新手的澄清：为什么叫"行为"？**
> 你可能在其他语言里见过"闭包（closure）"或"函数（function）"这类叫法。在 Synth OOP 里，**所有函数都是通过行为（也就是闭包）实现的，没有"函数"和"闭包"之分**——它们是同一个东西。所以我们不区分、也不额外引入名词，**直接统一叫它"行为"（behavior）**。一个行为就是一段可执行逻辑：它有输入、有输出、有函数体。无论它是普通函数、绑定在对象上的方法、还是传给控制流的条件分支，底层都是一个行为。这样想就简单了：**整个语言里，可执行的"单元"只有一种，就叫行为。**

行为本身也是对象：它可以像数据一样被**传递、组合、延迟执行**。
打个比方：行为就像一张"待办事项纸条"——你不需要现在执行它，可以把它塞进口袋（传给另一个行为）、写在墙上（存到变量里）、或者贴到日历上（作为方法绑定到对象上），等到合适的时候再拿出来执行。

### 5.2 三级行为模式
行为中间那个箭头不只是语法装饰——它是**行为模式箭头**，规定了这个行为对外的访问权限：能看什么、能改什么，全都写在箭头上。行为模式共三级，由严到宽排列：

| 行为模式 | 含义 |
| ---- | ---- |
| `=>` 零副作用模式 | 绝对不可访问任何外部事物，连访问都不可以，零副作用 |
| `~>` 常数模式 | 可以访问（只读）外部环境，不能修改 |
| `->` 非常数模式 | 既可以访问，也可以修改外部环境 |

三者展开说：
- **签 `=>`（零副作用模式）**：行为与外部世界完全隔离——不能访问任何外部变量，不能访问任何全局状态；**即使作为类的方法，连类的属性也不可访问**。它的整个世界只有自己的参数、局部变量和输出参数。这是最严格的行为模式，适合纯计算。
- **签 `~>`（常数模式）**：行为可以**访问调用者的环境变量**（读取），但**不能修改**它们；在类内部作为方法时，可以访问类的成员，但不能修改。
- **签 `->`（非常数模式）**：行为**不仅可以访问调用者的环境变量，还可以修改**它们；在类内部作为方法时，可以访问并修改类的成员。

> ⚠️ **给编译器和较真读者的澄清：常数模式（`~>`）的真实实现**
> 你可能觉得奇怪——"既然 `->` 能修改调用者的环境变量，那 `~>` 说'不能修改'，到底是怎么做到的？"这里有一个和直觉不同的实现细节：
> **在编译器实现层面，常数模式（`~>`）的效果是：行为可以访问变量，也可以"修改"变量——但这些修改是静默的，不会真正写回外界。** 具体来说：
> - 当 `~>` 行为运行的时候，它拿到的是**调用者环境变量的一份拷贝**；
> - 行为里对环境变量的任何修改，**都只发生在这份拷贝上，是静默生效的**——修改在行为自身范围内有效（行为内后续代码能看到修改后的值），但**绝不会影响到外界**；
> - 只有对行为**自身的变量**（它自己声明的局部变量、参数、输出参数）的修改，才在自身范围内正常生效。
> 换句话说，`~>` 相当于**给了行为一份环境变量的副本**：随便你怎么读写它，都不会污染调用者真正的环境。而 `->` 则没有这份"隔离"——它读写的是真实的环境变量。这就是"常数模式只读、非常数模式可写"在实现上的真正含义。

行为模式的选择权在声明者手里：如果不希望行为修改环境变量，只想让它读取，就选常数模式 `~>`；如果连访问都不想让它在外面看，就选零副作用模式 `=>`。

> 小贴士：行为模式这个概念，和 C++ 里写在成员函数上的那个 const 有一点点神似，但不是一回事。Synth OOP 的行为模式是行为自身的外部访问声明，跟着行为走（行为可以游离存在，不一定绑定为方法）；它与"方法变量的 const"是正交的两件事（见第 6.2 节）。

### 5.3 例子

```text
&io;
-(io::OStream out);
[() -> () { out << "Yes."; }];
```

没有输入，输出列表为空 `()`（行为不公布任何值），行为体里向 out 流出一句话。它要访问并写入调用者的环境变量 out，所以签非常数模式 `->`。

```text
[(a) ~> (sum) { sum << a.+(1); }]
```

输入一个数字 a，输出 sum。行为体只做计算、写入输出。签常数模式 `~>`（本例没有读取外部变量，但 `~>` 允许读）。注意：行为体里给输出变量赋值，用的仍然是 `<<`。

```text
[(a) => (sum) { sum << a.+(1); }]
```

同样的计算，如果签零副作用模式 `=>`，则向调用者表明：这个行为绝对不碰任何外部事物，是纯粹的计算。这是给调用者最强的安心保证。

### 5.4 元组（Tuple）
元组是 Synth OOP 中的**原生对象**，属于语言直接内建的不可变值序列容器。它被正式纳入原生对象表（见 2.2 节），与 `std::Array`、`std::Dict` 等并列，由编译器直接实现。

#### 5.4.1 元组的本质
元组是一种**按位置排列的、不可变的、轻量的**值打包方式。它的存在意义就是把多个值绑在一起，在数据流中作为一个整体传递，然后在接收端按位置拆开。
**元组 vs 类 vs 字典**

| 维度 | Class（类） | Dict（字典） | Tuple（元组） |
| ---- | ----------- | ------------ | ------------- |
| 本质 | 行为 + 状态的封装 | 动态键值对的集合 | 按位置排列的不可变值序列 |
| 访问方式 | 方法名/属性名 | 键 | 从 0 开始的连续整数索引，或结构化解耦 |
| 可变性 | 可变（可修改成员） | 可变（可增删键） | 绝对不可变 |
| 底层开销 | 虚函数表 + 成员变量 | 哈希表 | 连续内存数组（极快） |
| 创建方式 | 实例化表达式 `-(Type name)` | 字面量 `{...}` | 字面量 `(val1, val2)` 或方法多返回值 |
| 错误处理（历史"毒水模型"已退役） | 错误在源头即时抛出 + 类 g++ 诊断（含执行栈） | 同左 | 同左 |

#### 5.4.2 元组的初始化
元组的初始化方式与 `std::Array` 非常相似，唯一的区别是**用圆括号 `()` 代替方括号 `[]`**：

```text
// 元组字面量：用圆括号包裹多个值
-(std::Tuple point) << (10, 20); // 数字元组
-(std::Tuple mixed) << ("Alice", 25, true); // 混合对象元组
-(std::Tuple nested) << ((1, 2), (3, 4)); // 嵌套元组
```

元组内的元素可以是任意混合对象，编译器会自动推断元组的类型。元组一旦创建就不可变——任何试图修改元组内部值的操作都会触发编译期报错。

#### 5.4.3 元组的结构化解耦
元组支持**结构化解耦**语法，可以用与多返回值方法定义**相反的方式**将元组中的值按位置拆开：

```text
// 方法定义多返回值：(q, r) -> ...
$Math {
    @divide << [(a, b) -> (q, r) {
        q << a./(b);
        r << a.%(b);
    }];
}
// 实例化 Math，用实例调用方法
-(Math m);
// 解耦元组：用同样的位置对应关系拆开
-(std::Number q, std::Number r) << m.divide(10, 3); // 全都要
// 用下划线 _ 占位，忽略不需要的值
-(std::Number q, _) << m.divide(10, 3); // 只要商
-(_, std::Number r) << m.divide(10, 3); // 只要余数
```

解耦时，**方法签名必须严格匹配**——左侧声明的类型必须与元组中对应位置的类型一致，编译器会进行方法存在性检查。

#### 5.4.4 通过内置方法访问元组元素
除了结构化解耦，还可以通过元组的内置方法 `get` 按索引访问元素：

```text
-(std::Tuple t) << ("Alice", 25, true);
// 使用 get 方法，索引从 0 开始
-(std::String name) << t.get(0); // "Alice"
-(std::Number age) << t.get(1); // 25
-(std::Boolean flag) << t.get(2); // true
```

**方法签名必须匹配**：`get` 返回的是元组中对应位置的原始值，接收它的变量类型必须与该值类型一致。如果方法签名不匹配，编译器会报错：

```text
-(std::Tuple t) << ("Alice", 25, true);
-(std::Number name) << t.get(0); // 编译失败！t.get(0) 是 String，不能赋给 Number 类型
```

#### 5.4.5 元组作为方法参数和返回值
元组对象可以直接作为方法的参数传递，也可以作为方法的返回值：

```text
// 点类：make 返回元组，print 打印元组
&io;
-(io::OStream out);
$Point {
    @make << [(x, y) -> (result) {
        result << (x, y);
    }];
    @print << [(point) -> () {
        out << point.get(0);
        out << point.get(1);
    }];
}
// 使用
-(Point p);
p.print((10, 20)); // 直接传元组字面量
-(std::Tuple t) << p.make(5, 15); // 接收元组返回值
p.print(t); // 把元组传给另一个方法
```

#### 5.4.6 元组透传：多返回值直接传入另一方法
你可以把一个方法的多返回值直接作为另一个方法的参数传入。因为方法既可以定义接收独立的参数列表，也可以直接接收一个元组：

```text
// 定义接收独立参数的方法（放在 Math 类里，与 divide 并列）
&io;
-(io::OStream out);
$Math {
    @divide << [(a, b) -> (q, r) {
        q << a./(b);
        r << a.%(b);
    }];
    @process << [(x, y) -> () {
        out << x;
        out << y;
    }];
}
-(Math m);
// 将 divide 的多返回值直接传给 process——按位置严格对齐
m.process(m.divide(10, 3));
```

在这个例子中，`m.divide(10, 3)` 返回两个值（商和余数），这两个值作为独立参数传入 `m.process`。`m.process` 的形参 x 和 y 分别接收了这两个值。Runtime 底层的动作：当 `m.process` 被调用时，它直接接收两个独立的 Number 参数 x 和 y，不需要任何额外的包装或拆箱操作。

#### 5.4.7 底层模型
在 Synth OOP 中，一个行为本质上就是一个**传入元组、返回元组**的运行时结构。输入参数列表，本质上是对传入元组的声明（顺序与方法签名严格匹配）；返回值列表，本质上就是传出的元组。
这个设计的妙处：数据流完全透明。你不需要满篇找 return 语句来确定函数返回了什么，只需要看输出参数的名字，就能追踪它的值从哪来、到哪去。就像看水管走向一样直观——水从哪流进来，就从哪流出去。

### 5.5 算术与比较运算即方法调用

在 Synth OOP 中，**所有的算术运算与比较运算都是方法调用**，而不是传统语言中的中缀运算符。这意味着：

- `a + b` 必须写成 `a.+(b)` —— 调用 `a` 的 `+` 方法，传入 `b` 作为参数
- `a - b` 必须写成 `a.-(b)` —— 调用 `a` 的 `-` 方法，传入 `b` 作为参数
- `a * b` 必须写成 `a.*(b)` —— 调用 `a` 的 `*` 方法，传入 `b` 作为参数
- `a / b` 必须写成 `a./(b)` —— 调用 `a` 的 `/` 方法，传入 `b` 作为参数
- `a % b` 必须写成 `a.%(b)` —— 调用 `a` 的 `%` 方法，传入 `b` 作为参数
- `a < b` 必须写成 `a.<(b)` —— 调用 `a` 的 `<` 方法，传入 `b` 作为参数
- `a > b` 必须写成 `a.>(b)` —— 调用 `a` 的 `>` 方法，传入 `b` 作为参数
- `a <= b` 必须写成 `a.<=(b)`、`a >= b` 必须写成 `a.>=(b)`、`a == b` 必须写成 `a.==(b)`、`a != b` 必须写成 `a.!=(b)`

这种设计与你已经熟悉的 String 拼接语法（调用时写 `.+(另一个String)`）是完全一致的。String 的 `+` 方法用于拼接字符串，而 `std::Number` 的 `+` 方法用于数值加法——它们共享同一个方法名 `+`，但作用于不同的对象，由鸭子类型协商机制自动调度。

> 💡 **澄清：`std::Number` 就是"数字"，`std::Float` 已被替代**
> 本语言不再单独设置 `std::Float`（浮点类型）。`std::Number` 统一承载**整数与浮点等一切数值**——一个 `std::Number` 既可以是整数，也可以是小数。因此凡涉及数值，一律使用 `std::Number`，不要再使用 `Float` 或"浮点类型"这类旧称。算术方法（`+`、`-`、`*`、`/`、`%`）与比较方法（`<`、`>`、`<=`、`>=`、`==`、`!=`）都是 `std::Number` 的内置方法（详见第 2.3 节）。

**为什么这样设计？**

这与你前面学到的"万物皆对象"和"所有数据天生具备行为能力"的设计原则一脉相承。如果 `+` 只是一个中缀运算符，那么 `1 + "hello"` 在语法层面就是合法的（只是运行时方法签名不匹配）。但写成 `1.+( "hello" )` 后，调用者 `1` 是一个 `std::Number` 对象，它根本没有接收 String 参数的 `+` 方法重载，编译器可以在编译期直接报错。

**例子：**

```text
// 加法
-(std::Number a) << 10;
-(std::Number b) << 20;
-(std::Number sum) << a.+(b); // sum = 30

// 除法与取模：同样也是方法调用
-(std::Number q) << a./(b);
-(std::Number r) << a.%(b);

// 链式运算
-(std::Number result) << a.+(b).*(3); // (a.+(b)).*(3)
```

**注意：** 在 Synth OOP 中，`+`、`-`、`*`、`/`、`%` 这些符号**本身是方法名**，但方法名只有配合调用符号 `.` 才有效（`a.+(b)`）。任何将 `+` 当作中缀运算符的写法（如 `a + b`）都是非法的，编译器会报错。记住：**方法名就是 `+`，`.+` 里的点只是调用符号，不是方法名的一部分**。

### 5.6 行为的作用域
行为可以访问它定义位置之外的变量——这叫做"捕获外部环境变量"。**访问与修改的权限，完全由行为模式决定**：
- **零副作用模式 `=>`**：完全隔离。不能访问任何外部变量；作为类的方法时，连类的属性也不能访问。行为的世界里只有参数、局部变量和输出参数。
- **常数模式 `~>`**：可以**读取**调用者的环境变量，但不能修改；作为类的方法时，可以读取类的成员，不能修改。
- **非常数模式 `->`**：可以**读取并修改**调用者的环境变量；作为类的方法时，可以读取并修改类的成员。

```text
&io;
-(io::OStream out);
-(std::Number counter) << 0;
// 零副作用模式：连读 counter 都不允许（编译失败）
// [() => (v) { v << counter; }];
// 常数模式：可以读 counter，不能改任何环境变量
[() ~> (snapshot) { snapshot << counter; }];
// 非常数模式：可以读，也可以改 counter
[() -> () { counter << counter.+(1); }];
```

```text
// 类内部：行为模式同样约束对成员的访问与修改
$Counter {
    -(std::Number value);
    // 常数模式方法：可读成员，不可改
    @peek << [() ~> (result) { result << value; }];
    // 非常数模式方法：可读可改成员
    @inc << [() -> () { value << value.+(1); }];
}
```

### 5.7 行为的副作用
行为的副作用（Side Effects）是指行为在执行过程中对函数体外部状态的修改行为。Synth OOP 通过三级行为模式来严格约束副作用，确保代码的可预测性。

#### 5.7.1 零副作用模式行为：绝对隔离
当一个行为签的是零副作用模式 `=>` 时，它与外部世界完全隔离：
- 不能访问任何外部变量（连读取都不行）；
- 不能访问任何全局状态；
- 作为类的方法时，连类的属性也不能访问；
- 唯一的"输入"是参数，唯一的"输出"是输出参数。
编译器会强制保证这一点——任何尝试触碰外部事物的代码都会触发编译期报错。

#### 5.7.2 常数模式行为：只读
当一个行为签的是常数模式 `~>` 时，它可以读取调用者的环境变量（类内部则是类的成员），但不能修改它们。任何修改尝试都会触发编译期报错。

#### 5.7.3 非常数模式行为：可读可写
当一个行为签的是非常数模式 `->` 时，它可以读取并修改调用者的环境变量；作为类的方法时，可以读取并修改类的成员。
总结成一张表：

| 行为种类 | 能访问外部/成员吗？ | 能修改外部/成员吗？ |
| -------- | ------------------- | ------------------- |
| `=>`（零副作用模式） | 否 | 否 |
| `~>`（常数模式） | 能（只读） | 否 |
| `->`（非常数模式） | 能 | 能 |

核心思想：**行为模式是副作用的唯一开关，三档信任由你选择**。看到 `=>`，这个行为是个与世隔绝的纯计算；看到 `~>`，它只看不碰；看到 `->`，它可能动手。推理程序行为从此变得简单。

## 六、方法

### 6.1 声明方法
方法是绑定在对象上的行为。写法非常流式——**把一个行为流入方法名**：

```text
@<方法名> << <行为>;
```

> 💡 **给新手的澄清：方法不能脱离类独立存在**
> **方法必须绑定在某个类（或某个对象）身上，不能脱离类独立存在。** 你可以把方法想象成"长在类身上的能力"——没有类这个载体，就没有方法来挂靠。这一点与 C++/Java 里"成员函数属于类"是一样的：方法名必须在 `$类名 { ... }` 的定义体内声明（例如 `$Counter { @inc << ...; }`），或者绑定到某个对象身上。单独写一条 `@方法名 << 行为;` 而没有任何类去承接它，是**非法的**。
> 与之对照的是：**行为（behavior）本身可以游离存在**——它是可执行逻辑的单元，可以放在变量里、传给行为、作为参数传递（见 5.1 节）。但一旦它通过 `@方法名 << ...` 被声明成"方法"，就必须有一个所属的类/对象。简单记：**行为是自由的，方法是属于类的。**

### 6.2 方法修饰符
先澄清一个概念：**方法本身就是一个变量**（行为变量，它的值是那个行为）。方法修饰符作用在这个变量上，而不是行为内部：
- `!` 表示**这个方法变量是 const**——方法绑定不可被修改（不能把另一个行为重新流入这个方法名）。
- `#` 表示 **private**（不对外公开）。
两者可以组合：

| 写法 | 含义 |
| ---- | ---- |
| `@名字 << …;` | 普通方法 |
| `@!名字 << …;` | 方法变量为 const（不可重新绑定） |
| `@#名字 << …;` | private 方法 |
| `@!#名字 << …;` | private 且方法变量为 const |

注意区分：**行为模式是行为的属性**，描述行为对外的访问权限（`=>` / `~>` / `->` 三档），它跟着行为走——行为也可以游离存在，不一定要绑定为方法；**方法修饰符 `!` 是方法变量的 const**，管的是"这个方法绑定能不能被改"。两者正交，互不干扰。这与 C++ 里写在代码块前的那个 const 只是有点像，并不是同一个概念。

> 💡 **三种"不可修改"一次分清**：Synth OOP 里有三个长得像、但完全独立的"只读/不可变"机制，初学者容易混淆：
>
> | 标记 | 写在哪 | 管住什么 |
> | ---- | ---- | ---- |
> | `!`（类型名后） | `-(std::Number! x)` | **变量的值**不可修改（4.5 节） |
> | `@!`（方法名前） | `@!get << ...` | **方法绑定**不可重新绑定（本节） |
> | `~>`（箭头处） | `[() ~> (r) {...}]` | **行为对外部环境**只读不可写（5.2 节） |
>
> 三者作用对象不同、相互正交、可以任意组合。例如一个 `@!` 方法完全可以签 `->` 模式——绑定不可换，但行为体内可以修改成员。

### 6.3 四个保留方法名
有四个方法名被语言保留，各有专职：

| 方法名 | 角色 | 说明 |
| ------ | ---- | ---- |
| `::` | 构造函数 | 对象被创建时 |
| `~` | 析构函数 | 对象销毁时 |
| `=:` | 公布函数 | 对象向外公布信息 |
| `:=` | 接收函数 | 对象从外接收信息 |

`=:` 和 `:=` 互为镜像——一个公布、一个接收，共同构成对象之间的通信通道。

> 说明：这四个保留方法**统一定义在 `std::Object` 基类**（默认父类，见第 2.3.1 节），并以 `@!` 设为 const（不可修改），从而全局统一。任何类默认继承它们，无需自行声明。

### 6.4 例子

```text
$Example {
    @!:: << [() ~> () {}];
}
```

声明一个构造函数（属于 `$Example` 类），方法变量带 `!`（该绑定不可重新绑定），行为签常数模式，无输入、无输出、函数体为空。

### 6.5 传统方法调用也是表达式
在 Synth OOP 中，方法调用本身也是一个表达式，它的值就是方法执行后输出参数所携带的结果。这意味着方法调用可以出现在任何表达式出现的位置——你可以把方法调用的返回值直接流入变量、传给另一个方法、或者参与运算：

```text
// 方法调用的结果直接流入变量
-(std::Number result) << obj.getvalue();
// 方法调用嵌套在表达式中
-(std::Number sum) << obj.add(10).get();
// 方法调用的返回值直接传给另一个方法
other.process(obj.compute());
// 方法调用作为 if_ 的条件
(obj.check()).if_(
    [() ~> (value) { value << 1; }],
    [() ~> (value) { value << 0; }]
);
```

这与你之前接触过的 C++、Java 等方法调用语法完全一致——方法调用返回一个值，这个值可以继续参与数据流。在 Synth OOP 中，没有"语句"和"表达式"的严格区分，一切都可以是表达式，一切都可以参与数据流转。
小贴士：这一设计让代码可以像数学公式一样自由组合。你不需要为了中间结果额外声明变量，方法调用链可以一气呵成，数据从一端流入，从另一端流出，干净利落。

## 七、控制流：if_、while_、repeat_
在 Synth OOP 中，if、while、repeat 这类控制流不是僵硬的语法关键字，也不是独立的全局函数——它们是**方法**。为了与保留字区分，这些方法名统一带一个下划线后缀：`if_`、`while_`、`repeat_`。其中 `if_` 与 `while_` 是 `std::Boolean`（布尔值）的方法，`repeat_` 是 `std::Number`（数字）的方法。
为什么要这样设计？这意味着控制流可以像数据一样被传递、组合、延迟执行。你可以把 if_ 的分支行为存到变量里，传给另一个方法，或者按需选择是否执行。这带来了极大的灵活性。
控制流行为的写法完全遵循第五章的行为定义模式：`[(参数列表) 行为模式 (类型 输出名) { 行为体 }]`，参数列表本质是元组声明，**顺序与方法签名严格匹配，没有任何宽容机制**。没有 return 关键字，返回值由输出参数在执行结束时的值决定。
分支与循环体行为**直接访问调用者的环境变量**（按行为模式决定只读或读写），不再通过任何字典传递上下文。

### 7.1 if_ 语句
`if_` 是 `std::Boolean` 的方法。一个布尔值调用 `.if_()`，传入真分支行为和假分支行为：

```text
condition.if_(true_behavior, false_behavior)
```

其中 condition 是一个 `std::Boolean` 表达式，`.if_()` 是它的方法。if_ 恰好接收两个参数：真分支行为、假分支行为。条件本身不是参数，而是调用 `.if_()` 的那个布尔值。
参数说明：

| 参数 | 方法签名 | 说明 |
| ---- | ---- | ---- |
| 第一个 | 行为（真分支） | 条件为真时执行，输出 value 代表该分支返回值 |
| 第二个 | 行为（假分支） | 条件为假时执行，输出 value 代表该分支返回值 |

返回值：if_ 的返回值是执行分支行为输出参数 value 的值。
方法约束：两个行为输出的 value 必须一致。编译器会在编译期检查这一约束，确保一致性。
**示例 1（使用表达式作为条件）：**

```text
-(std::Number a) << 10;
-(std::Number b) << 20;
-(std::Number result) << (a.>(b)).if_(
    [() ~> (value) { value << a; }],
    [() ~> (value) { value << b; }]
);
```

在这个例子中：
- `(a.>(b))` 是一个 `std::Boolean` 表达式，它调用 `.if_()` 方法；
- 两个分支行为都直接读取调用者的环境变量 a 和 b（常数模式 `~>` 足够，因为只读）；
- 两个行为输出的 value 都是 `std::Number` 类型，满足方法约束；
- if_ 返回执行分支的 value，通过 `<<` 流入 result。
**示例 2（使用布尔常数作为条件）：**

```text
-(std::Number result) << (true).if_(
    [() ~> (value) { value << 1; }],
    [() ~> (value) { value << 0; }]
);
```

这里我们直接用布尔常数 true 作为条件，展示了 if_ 可以接受任何 `std::Boolean` 表达式——表达式、常数、甚至方法调用的返回值都可以。
**示例 3（使用方法调用返回值作为条件）：**

```text
$Checker {
    @check << [() ~> (result) {
        -(std::Number x) << 5;
        -(std::Boolean cond) << (x.>(3));
        result << cond;
    }];
}
-(Checker c);
-(std::Number result) << c.check().if_(
    [() ~> (value) { value << 1; }],
    [() ~> (value) { value << 0; }]
);
```

### 7.2 while_ 循环
`while_` 是 `std::Boolean` 的方法。一个布尔值调用 `.while_()`，传入**循环体行为**和**条件检查行为**——注意**条件检查行为排在循环体行为之后**：

```text
condition.while_(body, condition_check)
```

- `condition`（调用者）：`std::Boolean`，是进入循环的初始条件（为假则直接结束）；
- `body`（第一个参数）：循环体行为。它接收一个「循环状态」`state`，返回同类型的新 `state`——**其参数格式必须与返回格式一致**；
- `condition_check`（第二个参数）：条件检查行为。它接收 `body` 每一轮返回的 `state`，返回一个 `std::Boolean` 表示是否继续循环——**其参数格式必须与 `body` 的返回格式一致**。

参数说明：

| 参数 | 方法签名 | 说明 |
| ---- | ---- | ---- |
| 第一个 | 行为（循环体）`[(state) -> (state)]` | 接收 state，返回同类型的新 state；参数格式与返回格式必须一致 |
| 第二个 | 行为（条件检查）`[(state) ~> (flag)]` | 接收 state（即 body 的返回），返回 Boolean flag 表示是否继续 |

执行流程：
1. 判断调用者 `condition`（初始条件），为假则直接结束；
2. 执行循环体 `body`，得到它返回的 `state`（`state` 的初值遵循零值法则）；
3. 把 `state` 传给条件检查行为 `condition_check`，得到 `flag`；
4. 若 `flag` 为真，用本轮 `state` 作为下一轮 `body` 的输入，回到步骤 2；否则结束；
5. 返回最后一次执行 `body` 的返回值。

> ⚠️ 编译器内部检查：① `body` 的「参数格式」必须等于其「返回格式」；② `condition_check` 的「参数格式」必须等于 `body` 的「返回格式」。这两项格式一致性由编译器在内部完成，格式不匹配即编译失败。

示例：

```text
-(std::Number result) << (true).while_(
    [(state) -> (next) {
        next << state.+(1); // 循环体：接收 state，返回 state+1
    }],
    [(state) ~> (flag) {
        flag << (state.<(10)); // 条件检查：用 body 返回的 state 判断是否继续
    }]
);
```

在这个例子中：
- 初始条件 `true` 允许进入循环，`state` 从零值 `0` 开始；
- 循环体接收 `state`，返回 `state+1`（参数格式 `std::Number` == 返回格式 `std::Number`）；
- 条件检查行为接收 body 返回的 `state`，判断 `state.<(10)` 是否继续；
- while_ 返回最后一次循环体返回的 `state`（本例为 `10`）。

> ⚠️ 编译器开发者注意：`body` 的返回会作为下一轮 `body` 的输入与 `condition_check` 的输入，编译器需保证这条「状态链」上的类型格式一致，循环才能正确收敛。

### 7.3 repeat_ 循环
`repeat_` 是 `std::Number` 的方法。一个数字调用 `.repeat_()`，传入**循环体行为**——数字本身代表**循环次数**：

```text
count.repeat_(body)
```

- `count`（调用者）：`std::Number`，代表循环执行的次数；
- `body`（参数）：循环体行为。它接收一个「循环状态」`state`，返回同类型的新 `state`——**其参数格式必须与返回格式一致**。

参数说明：

| 参数 | 方法签名 | 说明 |
| ---- | ---- | ---- |
| 第一个 | 行为（循环体）`[(state) -> (state)]` | 接收 state，返回同类型的新 state；参数格式与返回格式必须一致 |

执行流程：
1. `state` 从零值开始；
2. 执行循环体 `body`，得到它返回的 `state`；
3. 用本轮 `state` 作为下一轮 `body` 的输入，重复执行，直到累计执行了 `count` 次；
4. 返回最后一次执行 `body` 的返回值。

> ⚠️ 编译器内部检查：`body` 的「参数格式」必须等于其「返回格式」，格式不匹配即编译失败。

示例：

```text
-(std::Number result) << 5.repeat_(
    [(state) -> (next) {
        next << state.+(1); // 循环体：接收 state，返回 state+1
    }]
);
```

在这个例子中：
- `5` 是循环次数，`state` 从零值 `0` 开始；
- 循环体接收 `state`，返回 `state+1`（参数格式 `std::Number` == 返回格式 `std::Number`）；
- 循环体执行 5 次，repeat_ 返回最后一次循环体返回的 `state`（本例为 `5`）。

### 7.4 参数严格性
if_、while_、repeat_ 的参数是**严格**的：
- `if_` 恰好接收两个行为参数（真分支、假分支），不多不少；
- `while_` 恰好接收两个行为参数（循环体、条件检查），且条件检查行为排在循环体行为之后；
- `repeat_` 恰好接收一个行为参数（循环体），循环次数由调用它的 `std::Number` 决定；
- 行为的参数列表、返回的方法签名都是固定的，必须严格匹配；
- 没有默认值，没有省略，没有任何宽容机制。

格式一致性要求（编译器内部检查）：
- `while_` / `repeat_` 的循环体行为，其**参数格式必须等于其返回格式**；
- `while_` 的条件检查行为，其**参数格式必须等于循环体行为的返回格式**。

## 八、类

### 8.1 声明类
类用 `$` 前缀声明，语法格式为：

```text
$<类名> [<父类>] {
    -(成员签名 成员名);
    @方法名 << 行为;
}
```

方括号中的父类是可选的。如果省略，该类直接继承自 `std::Object`。

### 8.2 父类可以是对象，也可以是实例
在 Synth OOP 中，`$<类名> [<父类>]` 里的父类位置，既可以填一个**类型名**，也可以填一个**实例**。这是 Synth OOP 类系统的一大特色。
- **填对象名**：表示新类继承该类型的结构与行为，这是传统的继承方式。
- **填实例**：表示新类基于该实例进行"逆向推导"，详见 8.3 节。

```text
$Animal {
    -(std::String name);
}
// 父类填对象：Dog 继承 Animal
$Dog [Animal] {
    -(std::Number age);
}
```

### 8.3 从实例派生类（逆向推导与继承）
当父类位置填的是一个**实例**时，Synth OOP 会进行"逆向推导"：
1. **反推类配置**：编译器根据该实例当前的成员结构（成员名、类型），反推出一份类配置；
2. **以实例当前值为初始值**：新类构造对象时，会以该实例当前的成员值作为初始值；
3. **以类模板为父类**：新类的父类是该实例所属的类模板，从而保留完整的继承链。

```text
$Student [Human] {
    -(std::Number age);
    -(std::String major);
    @:: << [(a, n, m) -> () {
        age << a;
        name << n; // name 继承自 Human
        major << m;
    }];
}
-(Student s);
s.name << "Alice";
s.age << 22;
s.major << "Computer Science";
// 基于实例 s 派生新类 GraduateStudent
$GraduateStudent [s] {
    @addResearch << [(topic) -> () {
        name << name.+(" (Research: ").+(topic).+(")");
    }];
}
```

在这个例子中，`$GraduateStudent [s]` 基于实例 s 派生。GraduateStudent 自动继承 name、age、major 三个成员，且以 s 的当前值（"Alice"、22、"Computer Science"）作为初始值；它的父类是 Student（进而继承 Human），继承链完整保留。addResearch 方法里用 `.+(另一个String)` 方法做字符串拼接（见第十一章示例与附录 A）。

## 九、约束（Constraint）

第一章说过，Synth OOP 采用鸭子类型：对象按"有没有所需的方法"来认，不看出身。约束（Constraint）就是把这种"所需的方法"**显式写成一张清单**——在其他语言里，这个角色通常叫"接口（interface）"。本章完整讲解约束的语法与用法。

### 9.1 约束是什么：一张方法清单

约束的语法与**类定义**（见第八章）非常相似，只是它只描述方法签名，不包含任何实现：

```
#Addable {
    @+ << [(other) -> (result) {}];
}
```

这里的 `#` 前缀表示"这是一个约束"，`@` 表示方法声明，`<<` 后面的行为只写了方法签名（参数 `other`、行为模式 `->`、输出 `result`），**函数体留空（`{}`）**——因为我们只关心"必须有什么方法、长什么样"，不关心它怎么实现。这表示：一个满足 `Addable` 约束的对象，必须有一个 `+` 方法，接收一个参数 `other`，返回一个结果 `result`。

> 💡 **给初学者的强类型体验**：可能你会担心"鸭子类型会不会太散漫，代码写起来没底？"别担心——**约束就是 Synth OOP 的"强类型盔甲"**。虽然是鸭子类型，但通过约束机制，你依然能享受到强类型语言的安心感：你可以显式声明"这个参数必须是能加的东西""这个对象必须能打印自己"，编译器会据此帮你做检查。也就是说，**鸭子类型给了你写的自由，约束给了你用的底气**。想要多自由都行，想要多严格也都能做到。

### 9.2 约束与类：像，但不是一回事

约束的写法和类（`$Name {...}`）几乎一样，初学者容易混淆。两者的区别一张表看清：

| 维度 | 类（`$`） | 约束（`#`） |
| ---- | ---- | ---- |
| 目的 | 定义对象的结构与行为：成员 + 方法的完整实现 | 只声明"必须有哪些方法"：仅方法签名，函数体留空 |
| 能否实例化 | 能：`-(Student s)` | 不能：约束只用于限定，不能写 `-(Addable x)` |
| 携带状态 | 有成员变量 | 没有任何成员 |
| 主要用途 | 造对象的"图纸" | 检查对象的"验收单" |

一句话记忆：**类是图纸，约束是验收单**。类告诉你"怎么造"，约束告诉你"造出来的东西必须会什么"。

### 9.3 约束的定义

约束可以包含多个方法签名，语法与类定义类似，只是每个方法只有签名、函数体为空（大括号内什么都不做）：

```
#Printable {
    @print << [() -> () {}];
    @toString << [() -> (result) {}];
}
```

约束可以用于限制行为的传入参数和传出参数的方法要求。

### 9.4 在行为参数中使用约束

在行为（或方法）的参数名后面加上 `[约束名]`，即可限制传入的参数必须满足该约束：

```
[(a[Addable]) -> (result) {
    result << a.+(1);
}]
```

这里，`a` 必须满足 `Addable` 约束，即 `a` 必须具有 `+` 方法。

### 9.5 约束名填类名：自动匹配该类的全部方法签名

约束名不一定非要自己新定义一个 `#Name`。**如果你在需要约束的地方直接填一个类名（比如 `std::String`、`Student`），编译器会自动把它识别为一个约束——即"与这个类的每一个方法签名都完全一样的要求"**。也就是说，任何"拥有与这个类完全相同的方法签名集合"的对象，都被视为满足该约束，而不管它到底是不是这个类的实例。

举例：`[(s[std::String]) -> () {}]` 表示传入的 `s` 必须拥有与 `std::String` 完全一致的方法签名集合。这意味着你传入的不一定是 `std::String` 本身——只要某个对象的方法签名和 `std::String` 一模一样，它也能被接受。

> 好处：这样一来，你不用每次为了一个"长得很像某类"的需求专门定义一个 `#Name` 约束，直接借类名当约束用即可，非常省事。这正好呼应了文档开头那句话——**鸭子类型让你按行为（方法签名）来认对象，而类和约束则是帮你把这些行为要求固定下来的模板**。

### 9.6 用其他约束当模板（约束继承）

约束也支持**继承**——就像类可以填父类一样（见 8.2 节），新约束可以在定义时填一个**父约束**，语法是 `#新约束名 [父约束名] {...}`。新约束自动继承父约束里的全部方法签名，再在花括号里补充自己的新签名：

```
#Addable {
    @+ << [(other) -> (result) {}];
}
#Comparable [Addable] {        // Comparable 继承 Addable 的全部签名
    @< << [(other) -> (result) {}];
}
```

这样，`Comparable` 约束自动包含 `Addable` 里的 `+` 签名，外加自己定义的 `<` 签名。凡是满足 `Comparable` 的对象，一定也满足 `Addable`。

### 9.7 行为限定符 `@`

在参数的类型限定方括号 `[]` 里，除了可以填约束名或类名，还可以填一个特殊关键字 `@`，表示**这是一个行为（闭包）限定符**——即该参数必须是一个行为：

```
[(handler[@]) -> () {
    // handler 必须是一个行为（闭包），否则编译失败
}]
```

如果 `@` 后面还跟着**行为签名**（即去掉 `@` 前缀后，保留行为的参数列表、行为模式与返回签名），则要求该参数必须是一个**拥有完全相同行为签名**的行为：

```
[(handler[@(x) -> (y)]) -> () {
    // handler 必须是一个行为，且签名必须为 (x) -> (y)（输入 x、输出 y）
}]
```

> 编译器内部会据此做两项检查：① 该参数**是行为**；② 该行为的**签名匹配**。这一机制主要用于控制流方法（如 `while_` / `repeat_`）对循环体行为、条件检查行为的格式约束（见第七章）。

### 9.8 检查时机：运行期的一次"点名单"

约束检查在**运行期**落实（当被约束的值已知时）。当解释器看到 `a[Addable]` 这样的限定时，它会做一次"点名单"：逐项检查 `a` 的方法签名集合是否覆盖 `Addable` 清单上的每一项，缺一项或多一项签名不匹配，都算不满足。注意，判定标准是**方法签名集合的匹配**，与对象"是不是某个类的实例"无关——这正是第一章鸭子类型"按行为认对象"在运行期的落实。

> ✅ **实现状态（当前解释器）。** 上述参数级「点名单」已在运行期完整落实：对方法参数写 `a[Addable]` 这类约束限定时，解释器在行为入口经 `check_constraint` 逐一核对实参的方法签名集合（按**类型**比对，而非参数名）；变量约束 `-(T[Addable] v)` 在声明时（无初始化器）及流 `<<` 绑定后同样经 `check_constraint` 核查。核查借 `ClassContract::validate` 实现——它只比较**参数类型（数量 + 入参 / 出参类型）**，不比较参数名，故真实实现（自由命名参数）也能满足契约。被约束值若不满足契约，立即抛 `ConstraintException`（`value does not satisfy constraint '…'`）。当前解释器落地的约束相关检查共三项：① **类级约束校验**（`define_class` 时 `validate`）；② **参数 / 变量约束的运行期点名单**（本节）；③ **原生 / 内建方法的调用边界签名检查**（见 9.9）。

### 9.9 原生 / 内建方法的调用边界签名检查（运行期）

第九章的约束检查（9.8）针对的是**用户用 `#约束名` 显式限定的参数**：它在运行期做一次「点名单」，验证对象的方法签名集合是否覆盖约束清单。但有一类方法签名是**解释器在运行期无从约束的**：

- 所有**原生（C++ 底层）标准库**方法的入参 / 出参类型（`file`/`system`/`maths`/`async`/`hash`/`structs`/`re`/`io` 等模块）；
- 所有**内建类**（`std::Number`/`std::String`/`std::Boolean`/`std::Array`/`std::Dict`/`std::Tuple`，以及 `io::OStream`/`io::IStream` 等）方法的入参 / 出参类型。

这些签名由 `CallableSign` 承载，在解释器**调用边界**（`RuntimeClass::call_method`）再做一次**运行期校验**，作为一道安全网（safety net），防止"乱七八糟的东西"被传进原生 / 内建方法、直到深处才抛出一个看不懂的运行期错误。

> 实现上，`runtime.hpp` 暴露一个 `g_sign_enforcer` 钩子（`std::function<bool(const CallableSign&, const InstanceListPtr&)>`），由 `builtin.hpp` 的 `init_builtins()` 在安装标准库前赋值为 `enforce_sign`。`call_method` 在分发到具体方法体之前调用它；一旦不通过，**立即在调用边界抛出 `RuntimeException`**（`Argument type mismatch for method '<name>': expected '…', got '…'`），而非让程序崩溃，也不再返回沿数据流传播的毒水对象（毒水模型已于 v1.27 退役）。

#### 运行期豁免类别（不会因这些而报错）

运行期签名检查刻意保留了与运行期约束一致的设计哲学——它只挡"明显错配"，不挡"语言本就允许的自由"：

- **生命周期 / 流操作符豁免**：`::`（构造）、`~`、`=:`（公布）、`:=`（接收）、`=` 这些特殊方法不参与签名检查。（历史上的 `_case` 已退役，不再作为豁免项。）
- **变长 / 行为 / 万能参数豁免**：声明为 `@`（行为限定符）、`value`（异构容器元素 / 键，字面量标签）、`std::Object`（任意对象）、以及以 `...` 结尾的变长形参，均跳过类型检查——它们本就接收任意类型。
- **缺失实参即报错**：实参个数少于签名要求时，**立即在调用边界抛出 `TypeException`**，不再像历史上的"毒水模型"那样跳过检查、交由方法体优雅降级（毒水兜底已于 v1.27 退役）。
- **`std::Array` ↔ `std::Tuple` 互通**：当参数类型声明为数组或元组时，实参是另一种也一律视为匹配——因为它们在运行时都是"通用容器胶囊"。

#### 命名空间容差匹配

类型名匹配时会**剥掉最后一个 `::` 之前的前缀**再比较：声明为 `OStream` 的形参，实参是 `io::OStream` 也算匹配（其余 `maths::Maths`、`async::Reactor`、`re::Pattern` 等同理）。这使得标准库既可以用库限定名 `module::Class` 实例化，原生签名里又不必处处写全限定名。

> ⚠️ 注意：运行期调用边界检查**不替代** 9.8 的运行期约束检查。二者职责不同——后者核对用户自定义的 `#约束名` 限定（比对方法签名集合）；前者专门兜底原生 / 内建方法签名这类约束检查覆盖不到的部分。两者叠加，才构成"编写时自由、运行时安全"的完整保障。

## 十、模块导入语句与命名空间

### 10.1 模块导入语句
模块导入语句用于引入外部模块或命名空间，语法为：

```text
&<模块名>;
```

例如：

```text
&io; // 引入 io 命名空间（OStream、IStream）
```

导入之后，该命名空间下的对象与方法就可以在当前作用域中使用了。所有使用到 `io::OStream`、`io::IStream` 的示例，都需要先 `&io;` 导入。

> 注意：`$Program` 对象与所有 `std::` 原生对象无需显式导入即可使用；只有外部库才需要用 `&` 导入。

### 10.2 命名空间：一个文件就是一个命名空间
Synth OOP **不提供主动声明命名空间的关键字**（没有类似 C++ 的 `namespace` 或 Java 的 `package` 块）。命名空间的划分是**自动**的：**每一个源文件都被自动包装到它自己的命名空间里**。

这样做有几点好处：
- **天然隔离**：不同文件里定义的类、约束、方法，默认互不干扰——同一个名字在两个文件里各说各话，也不会冲突。命名空间的名字通常就是文件的名字（不含扩展名）。
- **跨文件使用要靠导入**：如果你想在一个文件里使用另一个文件定义的类，需要先用 `&<那个文件的名字>;` 把它导入进来，再通过 `文件名::名字` 来引用（例如 `&shapes;` 导入后，用 `shapes::Vector` 引用其中定义的 Vector 类）。
- **std / io 是"预置命名空间"**：`std::` 和 `io::` 是语言自带的核心命名空间，分别装着原生对象（`std::Number` 等）和输入输出流（`io::OStream`、`io::IStream`）。它们也可以看成两个"文件"，只是由编译器内置。

> 小结：**命名空间 = 文件名**。你不需要主动写任何"声明命名空间"的语法，编译器会自动把每个文件包成一个命名空间。想让别的文件访问你的内容，就在那边 `&文件名;` 导入即可。

## 十一、毒水模型与 _case：错误的传播与解毒

> **⚠ 本章已退役（v1.27）。** 本章描述的"毒水模型"与 `_case` 异常捕获方法，在**当前解释器实现中已不再存在**。错误现在于源头**即时抛出**，并以**类 g++ 的诊断格式**报告：
> `文件:行:列: error: 类型: 消息`，后接出错源码行 + `^~~~` 插入符，以及对解释器/运行期错误附上的**完整执行栈**（逐帧列出调用路径上的方法/构造器）。颜色默认开启，设 `NO_COLOR=1` 关闭。运行期合法性检查改用标准库 `&assert;` 的 `Checker` 对象（`has_method(target, name)` / `has_changed(target)`），而非依赖沿数据流传播的受检值。
>
> 下面保留本章原文仅作**历史设计留存**，描述旧版意图；请勿据此编写新程序。当前正确行为见上文各处 v1.27 注记与 README 的「g++ 风格错误」一节。

学习实例化表达式（4.6 节）和除法（2.3 节）时，你曾在旧版文档里几次见到"毒水"的身影。本章把这套（现已退役的）机制从头到尾讲清楚，以便理解语言演进。

先建立整体图景（历史视角）。Synth OOP 曾规划两大安全基石，一静一动：
- **零值法则**（4.4 节）：保证对象**诞生时**安全——消灭"未初始化的垃圾值"；
- **毒水模型**（本章，已退役）：曾希望保证对象**出错后**安全——消灭"未处理的运行时错误"。

零值让每个对象从第一刻起就有确定、安全的值；毒水曾希望让错误一旦发生就不会静默丢失、也不会让程序崩溃。两者合起来，曾想凑齐"编写时自由、运行时安全"承诺里"安全"的那一半。

### 11.1 毒水模型（Poison Water Model，已退役）
Synth OOP 的（旧版）报错机制曾被称为"毒水模型"。它的核心思想是：**每个对象都携带着自己的"健康状态"，一旦某个对象因为错误而"中毒"，这种毒性会沿着数据流传染给所有依赖它的对象，直到有人主动处理它为止。**

#### 11.1.1 隐式 error 属性（已退役）
每个对象都有一个隐式的 error 属性。你可以把它想象成对象内部的一个"毒水标记"：
- 当对象正常时，error 为空（无毒）；
- 当对象发生错误时，error 被设置为错误信息字符串（有毒）。
例如，当 `10./(0)`（除以零）执行时，返回的 Number 对象的 error 属性会被设置为"除数为 0"，这个对象就变成了"毒水对象"。

#### 11.1.2 传染模型
毒水模型的关键在于"传染"——毒性不会停留在原地，而是会沿着数据流扩散：
- 如果一个毒水对象被赋值给另一个变量，目标变量也会变成毒水对象；
- 如果一个毒水对象参与运算，运算结果也会变成毒水对象；
- 如果一个毒水对象被传入行为，行为的返回值也会变成毒水对象。
传染的规则很简单：**任何操作如果接收到了毒水对象作为输入，那么输出也会自动带上毒性**。这样，错误信息（error 的内容）会沿着数据流一路传递，不会丢失。
这意味着你不需要在每个操作后手动检查错误——编译器/Runtime 会自动追踪毒性传播。当你最终使用一个毒水对象时（比如打印它），程序会报告错误而不是崩溃。

#### 11.1.3 毒水模型的例子

```text
&io;
-(io::OStream out);
-(std::Number a) << 10./(0); // a 是毒水对象，error = "除数为 0"
-(std::Number b) << a.+(1); // b 也是毒水对象（传染）
out << b; // 打印 b 时，会输出错误信息
```

在这个例子中，`10./(0)` 返回一个毒水 Number，a 在声明的那一刻就携带了毒性。`a + 1` 的运算结果 b 也被传染了毒性。最终 `out << b` 时，程序会优雅地报告错误，而不是崩溃。

#### 11.1.4 毒水与协商失败降级：两种不同的"出错"
初学者容易把毒水模型和第三章的"协商失败优雅降级"混为一谈。它们是两套机制，处理的错误不同：

| 维度 | 协商失败降级（3.3 节） | 毒水模型（本节） |
| ---- | ---- | ---- |
| 触发原因 | 流动时类型不兼容（如把 String 流给 Number 变量） | 运行时计算错误（如除以 0） |
| 发生阶段 | 流语句的智能协商阶段 | 方法执行阶段 |
| 处理方式 | 平滑降级：接收方保持零值，不产生毒性（见 D.8） | 产生毒水对象，毒性沿数据流传播 |
| 是否需要你处理 | 不需要，系统自动兜底 | 由你决定：传播到底，或用 `_case` 就地解毒 |

一句话区分：**协商失败是"倒不进去"，毒水是"算错了但继续流"**。前者系统自动降级，后者把选择权交给你（11.2 节）。

### 11.2 _case 方法（Rescue）
当毒水沿着数据流传播时，总需要在某个地方"解毒"。Synth OOP 提供了 `_case` 函数（正式名称）来实现异常捕获和处理。`_case` 是每个对象都有的内置方法，它接收一个行为作为参数，这个行为就是异常处理行为。

#### 11.2.1 _case 的基本用法
`_case` 的调用方式是：`对象._case(行为)`。行为接收一个参数（异常信息），并通过输出参数返回一个与原对象同类型的值。

```text
-(std::Number result) << 10./(0)._case([
    (error) -> (value) {
        // 只有对象中毒时，这个行为才会被调用，error 即异常信息
        value << 0; // 返回默认值解毒
    }
]);
```

#### 11.2.2 _case 的工作原理
1. 如果调用 `_case` 的对象没有中毒（error 为空），行为不会被调用，`_case` 直接返回原对象的值；
2. 如果调用 `_case` 的对象中毒了，行为会被调用，传入 error 信息；
3. 行为内部可以获取异常信息，进行自定义处理；
4. 行为必须通过输出参数返回一个值，这个值的类型必须与调用 `_case` 的对象类型相同；
5. `_case` 返回行为输出的值。

#### 11.2.3 _case 的例子

```text
&io;
-(io::OStream out);
// 基本用法：除数为 0 时返回默认值
-(std::Number result) << 10./(0)._case([
    (error) -> (value) {
        out << "捕获到异常：".+(error);
        value << 0; // 返回默认值
    }
]);
// 输出：捕获到异常：除数为 0
// result 的值为 0
```

```text
// 链式调用：多个操作后统一处理
-(std::Number q) << 10./(2); // q = 5
-(std::Number q2) << q./(0); // 除数为 0，q2 中毒
-(std::Number result) << q2._case([
    (error) -> (value) {
        out << "链式异常：".+(error);
        value << -1;
    }
]);
```

```text
// _case 返回的对象方法签名必须与调用者对象一致
// 以下代码编译失败：_case 返回 String，但调用者是 Number
-(std::Number result) << obj._case([
    (error) -> (result) { // 方法签名不匹配
        result << "error";
    }
]);
```

#### 11.2.4 _case 处理行为的模式选择
细心的读者会发现，本章示例里 `_case` 的处理行为都签非常数模式 `->`。这不是硬性要求，而是场景使然：处理行为往往要输出错误信息（访问并写入 `out`）、读取周边状态来决定默认值——这些都要触碰外部环境，`->` 最省事。当然，如果你的处理行为只做纯计算（比如恒返回 0），签常数模式 `~>` 甚至零副作用模式 `=>` 也完全合法。`_case` 对处理行为的模式没有任何特殊规定，一切遵循第五章的通用规则。

#### 11.2.5 _case 与毒水模型的关系
`_case` 是毒水模型的"解毒剂"。毒水模型负责追踪和传播错误，`_case` 负责在指定位置捕获和处理错误。两者的配合方式：
- 毒水模型确保错误不会丢失——毒性会沿着数据流一路传递；
- `_case` 确保程序不会因错误而崩溃——在合适的位置捕获毒性并恢复；
- 如果毒性一直传播到程序终点而未被 `_case` 捕获，程序会优雅地报告错误并退出。
这种设计让你可以自由选择错误处理的粒度：是每步都检查（用 `_case`），还是让毒性一路传播到顶层统一处理。

### 11.3 综合示例：把一切串起来
下面这个完整的程序把本文档的核心机制全部演示了一遍：实例化表达式、while_ 循环、if_ 分支、三级行为模式、毒水模型与 `_case` 解毒。

```text
&io;
$Math {
    @divide << [(a, b) -> (q, r) {
        q << a./(b);
        r << a.%(b);
    }];
}
$Program {
    @:: << [() -> () {
        -(io::OStream out);
        -(Math m);
        -(std::Number total) << 0;
        // 一、repeat_ 循环：累加 1 到 5
        // 循环体签非常数模式，直接修改调用者的环境变量 total
        5.repeat_([(state) -> (next) {
            next << state.+(1);
            total << total.+(next); // 累加 1 到 5
        }]);
        // 二、if_ 分支：判断 total 的大小
        // 两个分支行为只读取环境变量 total，签常数模式即可
        -(std::String msg) << (total.>(10)).if_(
            [() ~> (value) { value << "big"; }],
            [() ~> (value) { value << "small"; }]
        );
        out << msg;
        // 三、毒水与 _case 解毒：除以 0 产生毒水，就地捕获
        -(std::Number safe) << m.divide(total, 0)._case([
            (error) -> (value) {
                out << "捕获到异常：".+(error);
                value << 0;
            }
        ]);
        out << safe;
    }];
}
```

预期行为：repeat_ 把 1 到 5 累加进 total（得 15）；if_ 判断 `15 > 10` 为真，输出 `big`；`m.divide(15, 0)` 产生毒水，`_case` 捕获并输出异常信息，safe 解毒为 0 后输出。整个程序不崩溃，错误被优雅处理。

## 附录 A：语法符号速查表

| 符号 | 名称 | 用途 |
| ---- | ---- | ---- |
| `-` | 实例化表达式前缀 | `-(类型名 变量名)` 声明并创建对象 |
| `()` | 圆括号 | 实例化表达式 `-(类型名 变量名)`；元组/按位置传参 `(val1, val2)` |
| `<<` | 左向流 | 赋值、流语句、方法绑定（`@名字 << 行为`） |
| `>>` | 右向流 | 流语句另一方向，与 `<<` 等价 |
| `=>` | 零副作用模式 | 绝对不可访问任何外部事物（连类属性也不可访问），零副作用 |
| `~>` | 常数模式 | 可访问（只读）调用者的环境变量/类成员，不可修改 |
| `->` | 非常数模式 | 可访问并修改调用者的环境变量/类成员 |
| `[ ]` | 行为界定 | `[(参数) 行为模式 (结果) { 函数体 }]` |
| `@` | 方法声明 | `@方法名 << 行为;` |
| `!`（类型后） | 常数变量 | `-(std::Number! x)` 声明常数变量 |
| `!`（@后） | 方法变量 const | 方法本身是一个变量，`@!` 表示该绑定不可重新绑定 |
| `#` | 约束前缀 / private 修饰 | `#Addable {...}` 声明约束；`@#` 表示 private 方法，可与 `!` 组合为 `@!#` |
| `#...[...]` | 约束继承 | `#新约束 [父约束] {...}` 继承父约束的全部方法签名 |
| `&` | 模块导入 | `&库名;` |
| `::` | 构造函数/命名空间 | `@::`；`std::` |
| `~` | 析构函数 | `@~` |
| `=:` | 公布函数 | `@=:` |
| `:=` | 接收函数 | `@:=` |
| `=` | 赋值方法 | `a.=(b)` 显式赋值，与流式赋值 `a << b` 等价 |
| `_` | 解耦占位符 | `-(type, _)` 忽略不需要的返回值 |

注意：`=` 不是 Synth OOP 的运算符，中缀写法 `a = b` 非法；但可以显式调用赋值方法 `a.=(b)`，它与流式赋值 `a << b` 完全等价（见 4.3 节）。所有算术运算与比较运算都是方法调用，例如 `a.+(b)`、`a.-(b)`、`a.*(b)`、`a./(b)`、`a.%(b)`，以及 `a.<(b)`、`a.>(b)`、`a.<=(b)`、`a.>=(b)`、`a.==(b)`、`a.!=(b)`。详见第 5.5 节。

## 附录 B：关于计算能力
Synth OOP 是图灵完备的。三个要素齐备：
1. **条件分支**：if_ 是布尔值的方法，选择能力成立；
2. **无限循环**：while_ 是布尔值的方法（接收循环体与条件检查行为），repeat_ 是数字的方法（接收循环次数），函数体为行为，非常数模式允许状态修改；
3. **无界存储**：std::Array 等容器可无限增长，零值法则保证存储始终可用。
分支 + 循环 + 无界存储，即构成图灵完备。即便未来对零副作用模式 `=>` 或常数模式 `~>` 行为施加额外限制（如终止性要求），语言整体依然完备。

## 附录 C：对比示例——Synth OOP vs C++
选 C++ 做对比有两个原因：Synth OOP 的 `<<` / `>>` 流语法与 C++ 的 iostream 同源；C++ 有成熟的 const 体系，方便对照行为模式的语义。

### C.1 变量与输出

```cpp
// C++
#include <iostream>
#include <string>
int main() {
    std::string strlock = "Yahoo!";
    std::cout << strlock << std::endl;
    return 0;
}
```

```text
// Synth OOP
&io;
$Program {
    @:: << [() -> () {
        -(std::String strlock) << "Yahoo!";
        -(io::OStream out);
        out << strlock;
    }];
}
```

对照要点：
- C++ 用 `=` 初始化；Synth OOP 用 `<<` 把数据流入变量（`=` 在 Synth OOP 中不是运算符）；
- C++ 的入口是全局函数 main；Synth OOP 没有全局作用域，入口是 `$Program` 对象——编译器启动即实例化，执行即生命周期，入口逻辑写在它的构造行为里。

### C.2 纯函数：const 由签名保证

```cpp
// C++：纯函数靠程序员自觉，编译器不管
int add3(int a) {
    return a + 3;
}
```

```text
// Synth OOP：签零副作用模式，编译器保证行为绝对不碰外部世界
[(a) => (sum) {
    sum << a.+(3);
}]
```

### C.3 const 成员函数 vs 行为模式

```cpp
// C++：const 写在参数表后面
class Counter {
    int value = 0;
    public:
    int get() const { return value; }
    void inc() { value = value + 1; }
};
```

```text
// Synth OOP：是不是 const，写在箭头上
$Counter {
    -(std::Number value);
    @get << [() ~> (result) {
        result << value;
    }];
    @inc << [() -> () {
        value << value.+(1);
    }];
}
```

对照要点：C++ 的 const 是成员函数的后缀修饰；Synth OOP 的行为模式直接长在行为上——`~>` 只读，`->` 可写成员，`=>` 完全隔离，读写意图一目了然。

### C.4 多返回值

```cpp
// C++：得借 pair / tuple / 结构体
#include <utility>
std::pair<int, int> divmod(int a, int b) {
    return {a / b, a % b};
}
```

```text
// Synth OOP：多返回值通过多个输出参数实现，元组是语言内部的底层机制
$Math {
    @divide << [(a, b) -> (q, r) {
        q << a./(b);
        r << a.%(b);
    }];
}
// 实例化后调用，多返回值直接解耦——按位置严格匹配
-(Math m);
-(std::Number q, std::Number r) << m.divide(10, 3);
```

### C.5 控制流

```cpp
// C++：if 是关键字
if (a > b) {
    std::cout << "a wins";
}
```

```text
// Synth OOP：if_ 是布尔值的方法，分支行为直接访问调用者的环境变量
-(std::Number a) << 10;
-(std::Number b) << 20;
-(std::Number result) << (a.>(b)).if_(
    [() ~> (value) { value << a; }],
    [() ~> (value) { value << b; }]
);
```

对照要点：C++ 的控制流是语法结构；Synth OOP 的控制流是布尔值的方法——可以像数据一样被传递、组合、延迟执行。if_ 本身有返回值，返回执行分支的输出参数 value 的值。分支行为通过行为模式直接访问调用者的环境变量，不需要任何额外传参。

### C.6 实例化表达式

```cpp
// C++：声明和赋值是两步
int a = 10;
std::cout << a;
```

```text
// Synth OOP：声明即表达式，值是新创建的对象
&io;
-(io::OStream out);
-(std::Number a) << 10;
out << (-(std::Number b) << 20); // b 的声明表达式值直接参与流
```

对照要点：C++ 的声明是语句（statement），不产生值；Synth OOP 的声明是表达式（expression），本身就有值，可以直接参与数据流。

### C.7 元组透传

```cpp
// C++：得借 std::tie / std::forward_as_tuple
auto [x, y] = std::tie(a, b);
```

```text
// Synth OOP：元组是语言内建构造，可以透明地作为方法参数传递
$Math {
    @divide << [(a, b) -> (q, r) {
        q << a./(b);
        r << a.%(b);
    }];
    @process << [(x, y) -> () { /* 接收两个独立参数 */ }];
}
-(Math m);
m.process(m.divide(10, 3));
```

对照要点：C++ 需要借助 tuple / pair 等工具对象来打包多返回值；Synth OOP 的元组是语言内建构造，语法上直接用 `(...)` 表示，可以透明地作为方法参数传递，不需要任何额外的包装或解包操作。

- **冒号原则（词法层强制）**：除构造函数 `::` 外，单独的 `:` 一律不允许。
  合法的冒号序列只有 `::`（命名空间/构造函数，如 `maths::Maths`、`Program::@::`）、
  `=:`（公布）、`:=`（接收）。其它任何 `:` 都在词法阶段被拒，报
  `Unexpected ':' (colons are only allowed in '::', '=:', or ':=').`。
- **元组首项解构（单接收者）**：单个标量变量通过 `=` 方法或流语句被元组赋值时，
  取到的是元组的**第一个**元素；容器/流接收者（`Array`/`Tuple` 等）保留整个值，
  故 async 反应堆仍能完整返回“元组套元组”。
- **从 0 开始编号**：`Array`/`Tuple`/`String` 的序号与下标一律从 **0** 起。
  `arr.get(0)` 取首元素；`structs` 的 `Queue.pop()` 弹出 FIFO 队首。
- **`void` 不再是关键字——用空括号 `()` 表示「无值」**：`void` 已从类型 / 名称 /
  输出 / 约束标记中退役。要表示「无返回」或「无输出」，写**空参数/返回列表**即可，
  如 `-> ()` 或 `() -> ()`。返回列表为空的行为不产生公布值（故
  `out << 不返回值的行为` 不打印任何内容），且其列出的每个输出都照常公布。
  在类型、变量名、输出名、约束名位置写 `void` 现在都是**语法错误**：
  `'void' is not a type or name; use empty parentheses '()' …`。该规则由
  `parser.hpp` 在类型、变量、输出、约束四个位置统一强制。

- **自调用方法必须用 `self.` 前缀（裸名只指数据）**：实例方法必须用
  `self.name(args)` 显式调用（如 `self.greet()`、`self.squared(6)`）。裸写
  `name(args)` 现在是**错误**——它被解析为数据（局部变量/成员），而非隐式自派发，
  使数据/行为边界清晰。`self` 关键字指代当前实例（`self.n` 读成员）。构造函数 `@::`
  同样拥有 `self`，可调用实例自身方法。（此前裸 `name(args)` 会静默派发到 self，
  该歧义已消除。）

- **重复声明变量即报错（不再静默）**：在当前作用域重复声明已存在的名字（含解释器
  为行为预声明的输入/输出参数）会抛 `InterException: variable '<x>' is already
  declared in this scope`。顶层变量定义仍由语法器拒绝（`Top level only allows
  module import ...`）。

- **类定义结尾的 `;` 可选**：`$Class { … }` 与 `$Class { … };` 均合法（类定义为语句）。

- **构造初始化语法 `-(类型(实参)! 名)`**：变量可直接由构造实参构建：
  `-(std::Number(5)! n)` 造出值为 5 的常数 `std::Number`；
  `-(std::String("hello")! s)` 造出字符串 "hello"；`-(std::Array((1,2,3))! a)`
  用元组填满数组。实现会调用类构造函数：类若自定 `@::(args) -> ()` 则运行它；
  否则单参经常规流协商鸭子式流入实例（于是每个现有类都自动拥有可用的单参构造器）。
  Object 的无操作默认 `::` 有意不被派生类继承，构造实参绝不会被静默丢弃。
  六大核心类（`std::Number`/`std::Boolean`/`std::String`/`std::Array`/
  `std::Dict`/`std::Tuple`）现已各自注册显式 `@::(value) -> ()` 构造函数，
  复用其经实战验证的 `:=` 接收闭包，故 `-(std::Number(5)! n)` 与"先构造再接收 5"
  完全等价。

- **常数变量：只能构造、不能流赋值**：常数变量（`!(...)`）只能经构造器初始化
  （`-(std::Number(5)! n)`）；用尾部流语句赋值（`-(std::Number! n) << 5`）会抛
  `ConstException`，行为体内也不得用流覆盖常数成员。这修正了此前
  `-(std::Number! int); outer << int;` 输出一串 0 的缺陷。

- **右值不可赋值**：流语句（`<<`）左侧或赋值方法（`.=`）左侧必须是变量，不能是
  表达式结果。`1.+(1) << 0` 与 `1.+(1).=(0)` 均报 `InterException`——左侧是常数
  右值而非变量。

- **IEEE 754 浮点语义 + `NaN`/`Infinity` 关键字**：除以零得到 `+Infinity`
  （分子为负则 `-Infinity`），`0/0` 等不定型得到 `NaN`——不再下毒。`NaN` 与
  `Infinity`（亦作 `inf`）是关键字，解析为承载 IEEE 非有限值的真实 `std::Number`
  实例（与 `13` 即 `std::Number` 同理），可存储、比较、打印。与 `Infinity`/`NaN`
  的比较遵循 IEEE 规则（`NaN` 比较恒为假）。

- **递归护栏**：失控的自递归在达到 `RECURSION_LIMIT`（默认 1000；链接期把原生栈
  放大到 32MB 以便护栏干净触发）时被强制中断并抛 `RecursionLimitException`，
  整层调用栈回卷、不产出值，替代了栈溢出/卡死。

- **类 g++ 的诊断 + 完整执行栈**：语义错误（未定义名字、错误的自调用、
  常数/右值违规、递归超限、调用边界类型不符、方法缺失等）在源头*即时*抛出，而非
  静默传播“毒水”值。每个错误按类 g++ 的格式打印：
  ```
  build/_case.syn:5:1: error: RuntimeException: Method '_case' not found.
      | 1._case();
      | ^~~~
  note: execution stack:
      1. in '@::' (constructor of 'Program') [build/_case.syn:3:1]
  ```
  执行栈逐帧列出调用路径上的每个用户方法 / 构造器，使失败可被追踪，而非裸奔崩溃。
  默认带颜色高亮，设 `NO_COLOR=1` 可关闭（诊断文本不变）。算术故障（除零）遵循
  IEEE 754，不抛错。

- **实参类型约束违例即时抛 `TypeException`**：实参运行期类型与方法签名声明的
  参数类型不符时，在**调用边界**即被拒收，报
  `TypeException: Argument type mismatch for method '…': expected '…', got '…'`
  —— 不再有任何静默"毒水"降级。该检查经 `rt_basic::g_sign_enforcer` /
  `enforce_sign` 接入，覆盖所有原生 / 内置方法（流与生命周期方法、`std::Object`/
  `@`/`...` 形参及异构 `value` 标签豁免）。方法缺失则即时报
  `RuntimeException: Method '…' not found`。
